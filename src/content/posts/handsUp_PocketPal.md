## PocketPalのインストール
https://play.google.com/store/apps/details?id=com.pocketpalai&hl=ja
## モデルのインストール
メニューの `モデル` > `[+]` > `Huggingfaceから追加`
## ベンチマーク
メニューの`ベンチマーク`から実施 \
全て`unsloth`のモデルを利用 \
端末情報
- Xiaomi Redmi Pad 2 Pro(SD7s gen4+8GB)
- Redmagic6 (SD888+12GB)

| 端末        | Qwen3.5_0.8B_Q4_K_M | Qwen3.5_2B_Q4_K_M | Qwen3.5_4B_Q4_K_M |
| --------- | ------------------- | ----------------- | ----------------- |
| SD7s gen4 | 12.63 token/s       | 5.7 token/s       | 1.84 token/s      |
| SD888     | 18.70 token/s       | 10.24 token/s     | 1.00 token/s      |

| 端末        | gemma-4-E2B-it-Q4_K_M | Ministral-3-3B-Instruct-2512-Q4_K_M | granite-4.0-h-350m-Q4_K_M | granite-4.0-h-1b-Q4_K_M |
| --------- | --------------------- | ----------------------------------- | ------------------------- | ----------------------- |
| SD7s gen4 | 3.51 token/s          | 3.85 token/s                        | 23.58 token/s             | 6.99 token/s            |
| SD888     | 0.65 token/s          | 5.42 token/s                        | 36.40 token/s             | 11.62 token/s           |

推論性能は888が高いがSwap領域を最低限にしているため、大きいモデルでは逆転している
## 実用
性能とToken/sを見た時に`Qwen3.5_0.8B_Q4_K_M`と`Qwen3.5_2B_Q4_K_M`が良さげに見えた \
それぞれ質問を投げかけた所、2Bモデルのみ応答を出力できた (詳細はAppendix Aを参照)

NonThinkingで試すと、どちらも応答を生成できた(やや日本語が怪しい部分は両モデル合った) \
応答時間を気にしなければ2Bくらいが丁度良いと感じた(詳細はAppendix Bを参照) \ 
なので、2Bモデルの設定を詰めて使ってみる \
設定ページから変更
```
--ctx-size 1024 \
--batch-size 256 \
--n-predict 512 \
--flash-attn \
--kv-type q4_1
```
プリセットから変更 ([qwen3.5, Non-Thinking用](https://huggingface.co/unsloth/Qwen3.5-2B-GGUF))
```
temperature=1.0,
top_p=1.00,
top_k=20,
presence_penalty=2.0,
repetition_penalty=1.0
```
劇的な`token/s`の改善などは無いが、応答はやや安定した気がする (詳細はAppendix Cを参照)
